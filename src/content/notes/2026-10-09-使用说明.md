欢迎。这个网站的所有内容都在你电脑本地的 Markdown 文件里,**没有数据库、没有账号、没有服务器**。你只需要会写 Markdown,然后跑一条命令就能生成可以分享的网页。

## 一、目录结构速览

```text
09学习经验网页/
├─ src/content/notes/     ← 你的笔记都放这里,一篇一个 .md
│  └─ images/             ← 笔记里用到的图片
├─ src/data/              ← 其他模块的内容(都是 JSON,直接改)
│  ├─ site.json           ← 站点名、口号、页脚、社交链接
│  ├─ gallery.json        ← 生活相册
│  ├─ guestbook.json      ← 留言板
│  └─ interactions.json   ← 评论/留言板的开关
├─ public/gallery/        ← 相册的图片文件
├─ scripts/new-note.mjs   ← 一条命令新建笔记
├─ dist/                  ← npm run build 的产物(发布到网上用)
└─ dist-local/            ← npm run build:local 的产物(双击就能看)
```

日常需要碰的只有 `src/content/notes/` 和 `src/data/`。其余文件决定网站长什么样,不改也没关系。

> 也可以不碰文件,直接打开**后台**(网址 `/admin/`)用表单来写——见第十节。

## 二、第一次使用:安装

确保电脑上装了 Node.js(18 以上即可)。在项目目录打开终端,运行一次:

```bash
npm install
```

这会把需要的依赖下到 `node_modules/`,以后不用再装。

## 三、新建一篇笔记

最省事的方式是用自带脚本:

```bash
npm run new "动态规划入门"
```

它会在 `src/content/notes/` 下生成一个 `2026-10-09-动态规划入门.md`,文件头部已经填好了日期和标题,你直接往下写正文就行。

当然也可以手动新建一个 `.md` 文件,只要文件最上方有这段「头信息」(frontmatter):

```yaml
---
title: 动态规划入门
date: 2026-10-09
category: 算法
tags: [动态规划, 刷题]
summary: 一句话摘要,会显示在首页卡片上
sticky: 0
draft: false
---
```

每个字段的含义:

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 标题 |
| `date` | 是 | 日期,格式 `YYYY-MM-DD`,决定排序和归档年份 |
| `category` | 否 | 分类,一篇只能有一个;不填默认「未分类」 |
| `tags` | 否 | 标签,可以多个,用方括号和逗号 |
| `summary` | 否 | 摘要,显示在卡片上;不填卡片就只有标题 |
| `cover` | 否 | 封面图,写相对路径如 `./images/dp.png` |
| `sticky` | 否 | 大于 0 则置顶显示;数字越大越靠前 |
| `draft` | 否 | 设为 `true` 则只在本地预览时可见,正式构建不会包含 |
| `updated` | 否 | 最后更新日期,填了会在文章页显示 |

> 文件名就是网址。`2026-10-09-动态规划入门.md` 对应 `/notes/2026-10-09-动态规划入门/`。建议用「日期-标题」命名,方便排序。

## 四、正文能写什么

正文是标准 Markdown,额外支持下面几样。

### 代码块

用三个反引号包起来,并注明语言,会自动高亮(亮暗模式各一套配色):

```python
def fib(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

### 数学公式

行内公式用单个 `$` 包住,例如 $O(n \log n)$;独立公式用两个 `$$`:

$$
\frac{\partial L}{\partial w} = \frac{1}{m}\sum_{i=1}^{m}(h_w(x^{(i)}) - y^{(i)})\,x^{(i)}
$$

### 图片

把图片放到 `src/content/notes/images/`,然后在正文里引用:

```markdown
![图片说明](./images/example.png)
```

### 表格、引用、任务列表

这些 GitHub 风格的 Markdown 语法都支持:

> 引用块适合放一句总结或者别人的观点。

- [x] 已完成的事项
- [ ] 还没做的事项

### 目录

文章页右侧会根据你的 `##` 和 `###` 标题**自动生成目录**,滚动时高亮当前段落。所以写长文时多分几个二级标题,阅读体验会好很多。

## 五、本地预览

写的时候想随时看效果,运行:

```bash
npm run dev
```

然后在浏览器打开 `http://localhost:4321`。改了文件会自动刷新。`draft: true` 的草稿在这里也能看到。

## 六、生成可以分享的版本

有两种分享方式,对应两条命令。

### 方式 A:打包成文件夹,发给别人双击打开

```bash
npm run build:local
```

生成 `dist-local/` 文件夹。把整个文件夹压缩发给别人,对方解压后**双击 `index.html`** 就能在浏览器里看,完全离线,不需要联网也不需要装任何东西。

### 方式 B:发布到网上,得到一个网址

```bash
npm run build
```

生成 `dist/` 文件夹,把它部署到任何静态托管即可。推荐两个免费的:

- **GitHub Pages**:把项目推到 GitHub,在仓库设置里开启 Pages,选择用 GitHub Actions 从 `dist/` 发布。
- **Cloudflare Pages**:连接 GitHub 仓库,构建命令填 `npm run build`,输出目录填 `dist`。

两种方式的网页内容完全一样,区别只是「别人怎么打开」。

## 七、改站点的名字、口号、页脚

打开 `src/data/site.json`:

```json
{
  "title": "学习笔记",          // 网站名,显示在顶栏和标签页
  "description": "……",          // 网站描述
  "author": "我",               // 页脚署名
  "slogan": "……",               // 首页大标题下面那句
  "footer": "……",               // 页脚文字
  "postsPerPage": 10,           // 首页每页显示几篇
  "social": { "github": "", "email": "", "bilibili": "" }   // 填了会显示在「关于」页
}
```

导航菜单在 `src/lib/site.ts` 的 `NAV` 数组里,想隐藏某个模块删掉对应那行即可。

## 八、换主题色和亮暗模式

页面右上角的太阳/月亮图标切换亮暗;**左下角的圆点**可以在 8 套主题色之间切换(云蓝、晨金、暮紫、草甸、霞粉、湖青、暖橘、雾灰)。整套配色参考了《光遇》的低饱和治愈风格。选择会记在浏览器里,下次打开还是你选的那套。

## 九、其他模块怎么填内容

每个模块对应 `src/data/` 下的一个 JSON 文件,改完重新构建即可。

### 生活相册 `gallery.json`

先把照片放进 `public/gallery/某个文件夹/`,再登记:

```json
{
  "title": "校园的黄昏",
  "date": "2026-09-20",
  "description": "随手拍的几张",
  "photos": [
    { "src": "/gallery/campus/01.jpg", "caption": "图书馆西侧" }
  ]
}
```

建议把照片压缩到 1600px 宽以内,不然构建产物会很大。点击照片会全屏预览,支持左右键切换。

### 留言板 `guestbook.json`

默认是「本地模式」:你把收到的留言(微信、邮件里的)手动抄进去。想让访客**在线直接留言**,见下一节。

## 十、后台管理

打开网站后在地址栏加 `/admin/`(导航里没有这个入口)。它有四个标签页:**写笔记 / 留言 / 相册 / 总览**。

用法:左边填表单,右边实时生成文件内容,点「下载」或「复制」,把文件保存到提示的路径(覆盖旧的),然后重新构建。

这个后台**不连任何服务器**,只是帮你生成文件;所以它在离线版里也能用。发布到网上前如果不想让别人看到后台,把 `src/pages/admin.astro` 删掉或改名即可(它不影响其他页面)。

## 十一、评论、点赞、在线留言

这三样是「别人写进来」的内容,纯静态站自己存不了,所以处理方式不同:

| 功能 | 默认状态 | 升级方式 |
|---|---|---|
| **点赞** | 可用。存在访客自己的浏览器里,每个人看到的是自己点的数 | 暂不提供全站统计 |
| **评论** | 文章底部显示一段接入提示 | 接 Giscus(免费) |
| **在线留言** | 留言板只展示 `guestbook.json` 的内容 | 接 Giscus(免费) |

**接 Giscus 的步骤**(约 5 分钟,不花钱,不要服务器):

1. 在 GitHub 新建一个公开仓库(可以就是这个项目的仓库),在仓库 Settings → General → Features 里勾选 **Discussions**。
2. 打开 [giscus.app](https://giscus.app),按页面提示安装 Giscus 应用、填仓库名、选一个 Discussion 分类。
3. 页面下方会生成一段 `<script>`,把里面的 `data-repo`、`data-repo-id`、`data-category-id` 三个值抄到 `src/data/interactions.json` 对应位置。
4. 把 `comments.provider` 和 `guestbook.provider` 改成 `"giscus"`。
5. 重新构建并发布。

访客用 GitHub 账号登录后就能评论和留言,内容存在 GitHub Discussions 里。离线版因为没网,这部分看不到,其他一切正常。

## 十二、常见问题

**构建时报错说某个字段不合法?**
检查头信息的格式——`date` 必须是 `YYYY-MM-DD`,`tags` 必须用方括号,`sticky` 必须是整数。构建会在出错的文件名处提示。

**图片显示不出来?**
确认图片放在 `src/content/notes/images/` 里,并且路径写的是 `./images/xxx.png`(前面带 `./`)。

**想删掉这篇说明?**
直接删除 `src/content/notes/2026-10-09-使用说明.md` 文件即可。不过建议留着,改成 `draft: true` 就不会出现在正式版本里。
